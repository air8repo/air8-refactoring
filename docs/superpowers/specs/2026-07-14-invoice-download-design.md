# 设计文档：发票文件批量下载工具

- 日期：2026-02-28
- 分支：历史迁移
- 状态：已完成（历史迁移）

## 第一部分：需求

### 简介

系统主菜单缺少批量获取发票文件的入口，业务人员需要逐个手动查找下载融资相关的发票附件，效率低下。本功能在主导航栏新增「工具」下拉菜单，提供发票文件批量下载工具：用户输入融资编号（每行一个），系统调用外部 n8n API 获取发票文件信息并下载，按 `invoice_no + financing_no` 分组打包为 ZIP 供用户下载。同时该菜单设计为可扩展入口，为后续新增其他工具做准备。

### 需求 1：Tools 菜单与发票下载页面

**用户故事**：作为系统用户，我希望能够批量输入融资编号并一键下载对应的发票文件，以便快速获取融资相关的发票附件，减少手动逐个查找下载的工作量。

**验收标准**：

1. 当用户登录后访问系统任意页面时，系统应在导航栏「数据导出」右侧显示「工具」下拉菜单，并包含「导出发票文件」入口。
2. 当用户点击「导出发票文件」时，系统应展示发票下载页面，包含融资编号输入区域（textarea）和下载按钮。
3. 当用户在输入区域填写融资编号（每行一个）并点击下载时，系统应调用外部 n8n API 获取对应发票文件并打包为 ZIP 返回浏览器下载，下载过程中显示加载状态提示。
4. 当未登录用户访问 `/tools/` 时，系统应重定向到登录页面。

### 需求 2：批量与分组处理

**用户故事**：作为系统用户，我希望批量输入大量融资编号时系统仍能正确高效处理，以便一次性完成大批量发票的获取。

**验收标准**：

1. 在融资编号数量超过 50 个的情况下，当用户提交下载请求时，系统应按每批 50 个自动分批，并行调用外部 API 后合并结果。
2. 当下载得到的发票文件属于多个 `invoice_no + financing_no` 分组时，系统应为每组生成一个子 ZIP，再整体打包为一个总 ZIP；仅单一分组时直接打包为一个 ZIP。
3. 当融资编号输入包含空行或多余空格时，系统应自动过滤空行并对编号去重后再调用 API。
4. 当文件名包含非法字符（`\/:*?"<>|`）时，系统应将其替换为下划线后再写入 ZIP。

### 非功能需求

- 文件下载使用 `ThreadPoolExecutor`（最多 10 并发线程）并行下载，提升处理速度。
- 功能需登录后才可访问（`@login_required`）。
- 页面文案需同时支持中文与英文。

### 边界与排除项

- 不涉及数据库读写，发票文件信息与下载链接完全来自外部 n8n API。
- 单个文件下载失败仅跳过该文件，不中断整体流程，也不重试。
- 不提供下载进度条，仅有加载动画提示。

## 第二部分：设计

### 概述

采用 Flask Blueprint 模式新增 `tools_bp` 蓝图，作为系统内工具类功能的统一入口，与核心业务蓝图分离。发票下载逻辑相对独立，直接实现在路由文件中，不单独设 Service 层。前端使用独立页面（而非弹窗）+ 隐藏 iframe 接收文件流的方式触发下载，避免页面跳转。

### 架构

- `backend/app/routes/tools.py`（新增）— `tools_bp` 蓝图，包含工具首页、发票下载页面（GET）、下载处理（POST）三个路由；内部实现分批调用外部 API、并行下载、分组打包 ZIP 的完整流程。
- `backend/app/templates/tools/index.html`（新增）— 工具首页，卡片网格布局展示可用工具，为后续新增工具（10+）预留扩展空间。
- `backend/app/templates/tools/invoice_download.html`（新增）— 发票下载页面：textarea 输入区、下载按钮、加载遮罩层、隐藏 iframe。
- `backend/app/routes/__init__.py`（修改）— 新增 `tools_bp` 定义与导入。
- `backend/app/__init__.py`（修改）— 注册 `tools_bp`，`url_prefix='/tools'`。
- `backend/app/templates/base.html`（修改）— 导航栏新增「工具」下拉菜单。
- `backend/app/i18n/{zh-CN,en-US,zh,en}.json`（修改）— 新增 `common.title.tools` 与 `tools.*` 系列翻译键。

处理流程：用户输入 → 去重过滤 → 按 50 个一批分批 → `ThreadPoolExecutor` 并行调用外部 API → 合并结果、提取 `download_url` → `ThreadPoolExecutor`（10 线程）并行下载文件 → 按 `invoice_no+financing_no` 分组 → ZIP 打包 → 返回浏览器。

### 数据模型

无。本功能不涉及数据库读写。

### 接口设计

内部路由：

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/tools/` | 工具首页，卡片列表 |
| GET | `/tools/invoice-download` | 发票下载页面 |
| POST | `/tools/invoice-download` | 处理下载请求，返回 ZIP |

外部依赖：`GET https://n8n.air8.cn/webhook/downloadInvoiceFiles`，参数 `token`、`financingNos`（逗号分隔），返回 `[{invoice_no, financing_no, download_url, file_name}]`。文件名提取优先级：`Content-Disposition` 响应头 → URL 路径最后一段 → 自动生成。

### 错误处理

- 未输入任何融资编号：页面提示「请输入融资编号」。
- 外部 API 返回空结果（融资编号无效）：页面提示「未找到任何文件」。
- 单个文件下载失败：跳过该文件，不影响其他文件继续打包。
- 网络超时：显示错误提示，不中断已完成部分的处理。
- 未登录访问：重定向登录页。

### 测试策略

以手动测试为主（未编写自动化测试用例），覆盖菜单显示、页面加载、单/多融资编号下载、超 50 个编号分批、空输入、API 空结果、中英文切换、未登录重定向共 9 个场景，全部通过。外部 n8n API 为手动验证，未做 mock 自动化回归。

### 影响分析

- 新增独立蓝图与模板，未修改任何既有业务路由或数据模型，对现有功能无侵入。
- `base.html` 导航栏结构变更，需回归验证其余菜单项显示与响应式布局不受影响。
- 初版为串行下载存在性能瓶颈，已通过并行下载优化（`e29a1fa`），后续同类工具可复用该并行模式。
